## 1. 프로젝트 정의와 사이트 역할 분담

**TeachAble Art Play** — 만 4~7세 유아 대상 24주 통합예술교육 프로그램. 외부 강사 없이 **담임교사가 직접 운영**하고, 수업 중 관찰이 성장 기록으로 남는 구조.

현재 웹 자산은 **두 개의 배포로 분리**되어 있습니다.

| 사이트 | 주소 | 역할 | 대상 |
|---|---|---|---|
| **공개 체험 사이트** (이 문서의 대상) | `teachable-art-play-experience.vercel.app` | 로그인 없이 24주 과정·교실 플레이어·성장 리포트를 **직접 써 보게** 함 | 원장·교사 (영업 1차 접점) |
| 서비스 소개(영업) 사이트 | `teachable-art-play-sales.vercel.app` | 상품·가격·도입 절차·상담 폼 | 원장 (의사결정) |

체험 사이트 푸터에서 소개 사이트로 나가는 링크가 있습니다(새 창). **반대 방향(소개 → 체험) 연결은 이 문서 범위 밖이지만 함께 점검해야 합니다.**

핵심 설계 의도: **「설명보다 체험」.** 원장에게 기능을 설명하는 대신, 교실 플레이어를 직접 눌러 보게 해서 "담임교사 혼자 운영 가능하다"를 체감시키는 것이 이 사이트의 존재 이유입니다.

### 2-1. ⚠️ 해결되지 않은 전략 충돌 (개발 전 반드시 확인)

체험 사이트의 메시지와 **2027 영업 기획서**가 서로 다릅니다. 둘 중 무엇이 최신 결정인지 확인 전에는 **홈 「도입 안내」 섹션 문구를 건드리지 마세요.**

| | 체험 사이트 (현재 라이브) | 2027 영업 기획서 (2026-10-20) |
|---|---|---|
| 2026년 | 누구나 무료 공개 체험 | **4주 파일럿**(유·무료 **미정**) — "할인이 아니라 검증 절차" |
| 가격 | 비공개, 「확정되면 안내」 | **확정가 공개**: STARTER 198,000 / STANDARD 600,000 / PREMIUM 1,500,000원(반 기준, VAT 별도) |
| 2027년 | 기관 구독형 전환 예정 | 유치원 **300곳 · 600반 계약** 목표 (1학기 180 + 2학기 120) |
| 전환 경로 | 체험 → 구독 | 전화 → 데모 → 파일럿 → 계약, **파일럿→계약 60%** 목표 |

기획서는 "파일럿 → 계약 40% 미만이면 **파일럿이 무료 체험으로 끝난 것**"을 위험 신호로 봅니다. 즉 **무료 체험이 길어지는 것 자체를 리스크로 정의**하고 있어, 체험 사이트의 「2026년은 누구나 체험하는 해」 메시지와 방향이 어긋납니다. → §7 Q1

## 4. 반드시 지킬 원칙 (모든 작업 공통)

### 4-1. 교육 내용
- **공식 교사용 수업가이드에 없는 수업 문장을 새로 지어내지 않습니다.** 체험용으로 각색한 문장은 반드시 「공식 가이드 기반 체험 구성 · 검수 전」 배지와 함께 둡니다.
- 「공식 교육과정」 「공식 결과물」 배지는 **가이드 원문으로 확인된 항목에만** 붙입니다.
- 정답을 유도하는 발문을 쓰지 않습니다. (가이드 원칙: 정답보다 아이가 본 변화를 말하게 한다)

### 4-2. 기록·평가 표현
- 점수·등급·순위·진단 표현 금지. 「우수」 「부족」 「또래보다」 같은 비교 표현 금지.
- 성장 기록은 **관찰된 장면과 아이의 말** 중심으로만 씁니다.

### 4-3. 개인정보
- 공개 페이지에 실제 원아 이름·얼굴·실제 기록을 쓰지 않습니다. 예시는 반드시 「가상」 표기.
- 체험 사이트는 **수집·저장을 하지 않는 것이 기능**입니다. 폼·로그인·쿠키 기반 추적을 추가할 때는 이 전제가 깨지지 않는지 먼저 확인하고, 깨진다면 고지 문구를 함께 바꿉니다.

### 4-4. 이미지
- 자체 제작 일러스트만 사용. 사용권이 확인되지 않은 캐릭터 이미지 사용 금지.
- 실사처럼 보이는 생성 이미지를 「실제 수업 현장」처럼 쓰지 않습니다. 쓰는 경우 「연출된 장면」 표기.

### 4-5. 기능 표기
- 운영에서 실제로 열리지 않는 기능을 있는 것처럼 쓰지 않습니다. 「순차 오픈」으로 표기하고 한곳에 모읍니다.
- 9주 이후 콘텐츠·리포트는 **「순차 제공」** 표기를 유지합니다.
- AI 관련 문구는 **「AI는 진단·평가하지 않습니다」**가 기본이고, AI 기록 정리 보조는 **「준비 중(STARTER 미포함)」**으로만 씁니다.

### 4-6. 영업 문구 금지 (2027 영업 기획서 기준)

아래는 체험 사이트에도 그대로 적용됩니다.

- **「정부 인증」 「공식 인정」** 표현 금지
- **교육 효과를 수치로 주장하지 않음** — 쓸 수 있는 숫자는 운영 지표(준비 시간, 기록 건수)뿐이고, 그마저 **실측 전에는 쓰지 않습니다**
- 도입 실적·성공사례·후기는 **실제 계약 + 서면 동의가 있는 것만**. 현재 외부 계약 실적이 없으므로 **사례 문구를 만들지 않습니다**
- **「키즈노트 등 기존 앱을 대체한다」는 표현 금지**
- 할인·파일럿 비용 조건을 화면에 쓰지 않음 (내부 결정 전까지 「상담 시 안내」)
- 자료 출처는 **[공식] / [추정] / [가정]**으로 구분해 표기하고, 가정값은 실측 후 교체합니다

### 4-7. 코드
- 기존 화면을 깨뜨리는 전면 재작성 금지. 기존 저장소를 확장합니다.
- TypeScript strict, `any` 금지. 서버/클라이언트 경계 명확히.
- 체험 화면이 운영 데이터와 섞이지 않도록 막는 장치(및 그 테스트)를 유지합니다. **이 테스트는 삭제·우회 금지.**
